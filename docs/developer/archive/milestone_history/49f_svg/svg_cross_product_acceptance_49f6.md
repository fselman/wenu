# SVG cross-product acceptance

**Milestone:** 49F.6
**Status:** implemented and accepted
**Acceptance date:** 2026-08-27

## Purpose

Milestone 49F.6 verifies that Wenu's designer-oriented SVG contract is
consistent across every supported chart product before work proceeds to
49G. The projection or physical-product layout may change, but common sky
content keeps the same semantic ownership, naming, style roles, editing
policy, and hierarchy.

The acceptance matrix is generated by
`tools/render_49f6_svg_matrix.py`. It covers:

- all-sky;
- planisphere;
- regional;
- circumpolar;
- binocular;
- south and north polar pages;
- polar pouch.

The seven matrix entries produce eight SVG files because the polar-page
entry emits one page for each hemisphere.

Every file passed these machine checks:

- exactly one provenance metadata element;
- no raster image elements;
- no duplicate IDs;
- no semantic artist missing a semantic path;
- no generic `nonstellar`, `other`, or `unknown` fallback path;
- no raw Matplotlib `figure_*`, `axes_*`, `patch_*`, `line2d_*`,
  `text_*`, or `matplotlib.axis*` object;
- a professional `wenu-chart` document wrapper;
- editable SVG text and declared `style` or `layout` policy.

The polar pouch intentionally has no `plot-area`: it is a fabrication
template rather than a projected sky plot.

## Cross-product findings resolved

The matrix exposed defects that smaller regional audits could not reveal:

1. Repeated semantic annotation of Magellanic Cloud outputs could serialize
   duplicate XML attributes.
2. A page background could be reordered above the astronomical plot and
   hide an otherwise correct all-sky SVG.
3. Unclipped binocular geometry produced 59,184 invisible star paths and a
   39.724 MiB file. Renderer-boundary culling reduced the accepted product
   to 0.180 MiB without changing the visible chart.
4. Matplotlib wrapper, axes, patch, line, and text names leaked into the
   designer hierarchy.
5. Polar pages lacked semantic planisphere-rim, declination-tick, catalog
   object, and physical-page ownership.
6. Curve and polygon clipping preserved geometry but misaligned
   per-entity constellation metadata.
7. Numeric catalog designation `1636-283` was valid source data but did
   not satisfy the internal alphabetic semantic-key rule. It now retains
   its visible designation and receives the safe internal key
   `catalog_1636_283`.
8. Local line styles prevented styling a constellation-line owner group.
   Identical inheritable line properties are now lifted conservatively to
   the semantic owner.

## Accepted hierarchy behavior

Common sky content uses the same hierarchy across projections. Examples
include:

- galaxies;
- Milky Way, LMC, and SMC, grouped by isophote value;
- shared deep-sky categories;
- stars;
- constellation lines, boundaries, and labels, grouped by constellation
  system and individual constellation;
- coordinate-grid lines and labels.

Polar pages additionally expose:

`Furniture → Planisphere rim → Daily tick marks / Day labels / Month labels`

The pouch exposes semantic fabrication and furniture content rather than
pretending to contain an astronomical plot.

## Inkscape acceptance

The eight products were inspected using Inkscape 1.4.4 for macOS. The
accepted checks include:

- correct and complete visual output;
- understandable, nonredundant hierarchy labels;
- correct constellation ownership in both hemispheres;
- consistent deep-sky taxonomy;
- selectable and editable text;
- group and individual style changes;
- planisphere-rim and pouch fabrication organization;
- normal opening, hierarchy navigation, saving, and closing.

Inkscape ancestor locking applies to the complete subtree even when a
child lock icon appears open. The accepted workflow is:

1. temporarily unlock the supplied semantic owner;
2. style the owner for a class-wide change or a child for one object;
3. do not transform scientifically fixed geometry;
4. relock the owner.

This is advisory editor locking, not cryptographic protection.
