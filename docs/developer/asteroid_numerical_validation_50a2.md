# Asteroid numerical validation (Milestone 50A.2)

**Status:** Implemented for Fernando's scientific and architectural review

**Base:** `a175721`

**Runtime effect:** Adds CSPICE type-21 segment evaluation and admits an
explicit minor-body-plus-planetary resource chain to the existing astrometric
direction realizer. It adds no body descriptor, catalog entry, chart request,
CLI/configuration option, projection, renderer, exporter, or visible output.

## 1. Discovered compatibility boundary

The real bounded SPKs generated by Horizons for both validation objects contain
NAIF SPK type-21 extended modified-difference segments. Skyfield 1.55 and
jplephem 2.24 can identify those segments but cannot evaluate them. Fernando
accepted on 2026-09-10 the smallest correction: SpiceyPy/CSPICE evaluates only
the exact small-body segment; Skyfield retains DE440, the observer, planetary
states, and apparent-place corrections; Wenu retains segment selection,
resource identity, and the explicit composition

\[
  (\mathbf r_{BO},\mathbf v_{BO}) =
  (\mathbf r_{BC},\mathbf v_{BC}) +
  (\mathbf r_{CO},\mathbf v_{CO}).
\]

`SpiceMinorBodyKernel` opens one local DAF/SPK explicitly, enumerates packed
segment descriptors, and evaluates the already-selected descriptor with
`spkpvn()`. It does not furnish the file to SPICE's global kernel pool and does
not ask SPICE to find or compose a path between bodies. Wenu verifies returned
frame and centre, converts km and km/s to AU and AU/day, and owns closure.
Fernando verified on macOS that SpiceyPy 6.0.3 with CSPICE N0067 exposes every
DAF and SPK routine used by this bounded adapter. The declared compatibility
range is therefore `spiceypy>=6,<9`; it does not require a newer release
without a demonstrated API need.

## 2. Validation objects and resources

The bounded set deliberately covers two different regimes:

| Object | Role | Horizons identity | Solution evidence | SPK segment |
| --- | --- | --- | --- | --- |
| (1) Ceres | stable main-belt asteroid | command `1;`, SPK `20000001` | JPL#48, 2021-04-13, 1,075 observations, RMS 0.24563 arcsec, condition code 0 | centre 10 (Sun), frame 1 (J2000/ICRF), type 21, JD 2460676.5–2462502.5 TDB |
| (99942) Apophis | fast nearby object | command `99942;`, SPK `20099942` | JPL#220, 2024-06-25, 7,370 observations, RMS 0.080135 arcsec, condition code 0 | centre 10 (Sun), frame 1 (J2000/ICRF), type 21, JD 2461771.5–2462502.5 TDB |

Apophis metadata also retains Horizons' non-default terrestrial J2 gravity
model and its reported `A1`, `A2`, and `A3` acceleration parameters. Wenu does
not reapply those terms; they are already represented by the integrated SPK.

`tools/acquire_50a2_asteroid_resources.py` is the only networked operation. It
requests Ceres for 2025-01-01 through 2030-01-01 and Apophis for 2028-01-01
through 2030-01-01 from the Horizons SPK API, validates the returned target ID,
writes the two local files, and records their complete response metadata and
SHA-256 digests. It refuses to overwrite an existing evidence set. Rendering
performs none of these operations.

Horizons wraps the JSON `spk` base64 value across lines. The acquisition tool
removes only whitespace before strict base64 decoding, then requires the
decoded payload to begin with the DAF signature; non-base64 content and a
non-DAF payload still fail closed.

Horizons embeds acquisition-specific material in a generated SPK, so a new
request can have a different whole-file digest even when it identifies the
same orbit solution. Each validation run therefore verifies its SPK against
the digest frozen in its own acquisition report; it never substitutes a newly
downloaded file silently.

The offline validator keeps these resource locations separate by design. Its
minor-body directory defaults to `~/.cache/wenu/minor_bodies/50a2`, while
`--planetary-ephemeris-path` defaults to `~/.cache/wenu/de440s.bsp`. This
matches Wenu's established planetary cache and does not copy DE440s into the
bounded acquisition directory.

## 3. Independent oracle

`tests/fixtures/horizons_asteroid_validation_50a2.json` freezes direct Horizons
API output retrieved on 2026-09-11. The returned API signature reports version
1.2. The vector oracle uses centre `@0`, geometric `VEC_CORR=NONE`, ICRF
`REF_PLANE=FRAME`, TDB, and AU/day. The observer oracle uses quantities 1, 20,
21, and 45, ICRF, airless apparent place, UTC, and both:

- La Ligua: east longitude -71.230289 degrees, latitude -32.443342 degrees,
  elevation 0.052 km;
- the terrestrial geocentre `500@399`.

Ceres is sampled at 2026-01-15, 2026-06-14, and 2026-11-11. Apophis is sampled
daily from 2029-04-10 through 2029-04-13, approaching from 0.01346 to 0.00321
au. The fixture, not Wenu's provider, supplies Cartesian state, astrometric
ICRS RA/Dec, airless apparent ICRS RA/Dec, observer distance, one-way light
time, and the independent topocentric/geocentric comparison.

## 4. Calibrated acceptance envelope

The evidence sets these absolute maxima:

| Quantity | Acceptance tolerance |
| --- | ---: |
| Cartesian position | 5e-12 au |
| Cartesian velocity | 5e-13 au/day |
| each astrometric/apparent RA or Dec component | 5e-6 deg (18 mas) |
| observer distance | 1e-9 au |
| one-way light time | 1e-7 min |
| topocentric/geocentric parallax | 5e-6 deg (18 mas) |

The direction envelope characterizes the complete comparison, including
Horizons' current planetary authority and Earth-orientation treatment versus
Wenu's installed DE440/Skyfield realization. It is not SPK interpolation
precision and must not be generalized silently to another solution, resource,
site, or time interval.

## 6. Test and documentation ownership

Existing ephemeris, direction, and minor-body test files extend only their own
contracts: scalar provenance from a resource chain, explicit observer-resource
membership, exact CSPICE descriptor evaluation and conversion, ICRF/type/centre
identity, closure, and failure behavior. They do not repeat projection,
rendering, chart, or complete-output tests. The installed SPKs remain external
validation resources and are not test fixtures or packaged data.

The focused minor-body diagram changes because the concrete SPK evaluator and
direction connection changed. The general architecture diagrams remain
correct. User documentation and examples require no edit because 50A.2 adds no
public selection, default, configuration, symbol, track, or visible result.

Acceptance authorizes only 50A.3 first-drawable-asteroid work; it does not
pre-accept designation, photometry, symbol, semantics, track, CLI, or output.
